# practices: front-end

building, serving, and verifying front-end code, graded by `rules.md`. read
this before building, serving, or verifying front-end code.

## experiments

| topic | rule | evidence | recheck when |
|---|---|---|---|
| standalone html | grade the file people will receive (the inlined standalone file), not only the linked source. an inlined stylesheet loses its `@import` unless the import leads the style block, and a google fonts url contains `;` inside its quotes, so match `@import url\([^)]*\);` whole and hoist it to the top. the symptom is a fallback sans in the render, and a render diff that jumps from about 1% to 6–20% | 2026-09-17, two debug rounds | next inlined-stylesheet build |
| background servers | start a background dev server with `cd <project> &&` in the same command. a harness that resets the working directory starts it in the wrong folder, and every route returns nothing | 2026-08-26, every route failed until a restart; one round | next background server start |
| stopping servers | stop a server by its port (`lsof -ti :<port> \| xargs kill`). pkill on the command misses a pnpm-spawned child, which keeps serving a stale build (the tell: fonts return 404 at 21 bytes) | 2026-08-26, a stale server kept serving an old build; one round | next server restart |
| long-page captures | the headless `--screenshot` flag blanks above about 12,000 device px and doesn't scroll to anchors; capture with a raw CDP clip against puppeteer's cached chrome-headless-shell, driven by a small dependency-free node websocket script, instead. `next dev` can truncate very large responses, so check page-end content against a production build | 2026-08-30 | next long-page capture |
| interaction probes | scope interactive selectors to `main` or `section`. a bare `button[aria-expanded]` matched the header's menu trigger before the page's own control | 2026-08-26, one capture round | next interaction probe |
| lighthouse floor | a next.js app-router page with a text LCP tops out around 96 on mobile performance on localhost, because Lighthouse's Lantern model charges every script started before LCP, and the react runtime alone is about 130KB gzipped. subsetting fonts and dropping unused weights is the cheap win (130KB to 40KB of fonts took one page from 86 to 96); beyond that, only removing hydration helps. desktop reaches 100 | 2026-08-26 | next performance pass |
| stale dev caches | put structural layout (stacking direction, wrapping) in markup, never in a css rule alone: turbopack dev can serve a stale css chunk after many hot edits, and the stale chunk can survive a dev-server restart. verify the served css (curl the chunk), not the file on disk, and restart the dev server after heavy css-edit sessions. if it still mismatches after a restart, `rm -rf .next` and restart. treat any build error naming a module you just deleted (`ReferenceError: X is not defined` during "collect page data") as a stale cache first: cold-build before reading code | 2026-07-09 a broken live page; 2026-07-10 a restart didn't refresh the chunk; 2026-07-26 four greps chasing a phantom module | next long dev-server session with css edits |
| iframe previews | `X-Frame-Options: DENY` blanks same-origin iframes too, so any page that previews the site in iframes needs `SAMEORIGIN`. after any headers or security change, check that iframe previews render. the browser shows "localhost refused to connect", and curl can't see the failure | 2026-07-10, a blocked morning review | next headers or security change |
| portaled popups | every portaled popup (menu, tooltip, dialog positioner) takes an explicit slot on the project's z scale. portals land at the end of body at z auto and paint behind every positive-z layer, so the popup opens invisibly. markup checks can't catch paint order; look at it | 2026-07-12, a dropdown shipped invisible behind the hero; a review round | next portaled overlay |
| text wrapping | chrome's `text-wrap: pretty` only prevents single-word last lines, so a two-word rag ships untouched. for even line lengths use `balance` (default it on `p`; chrome skips it past 6 lines, so long prose is safe) and pin `pretty` on known long-form text for orphan protection | 2026-07-29, a sitewide `pretty` pass changed nothing visible and cost a rework round | next typography rag pass |

# practices: front-end

building, serving, and verifying front-end code, graded by `rules.md`. read
this before building, serving, or verifying front-end code.

## defaults

| topic | rule | evidence |
|---|---|---|
| text wrapping | chrome's `text-wrap: pretty` only prevents single-word last lines, so a two-word rag ships untouched. for even line lengths use `balance` (default it on `p`; chrome skips it past 6 lines, so long prose is safe) and pin `pretty` only on known long-form text for orphan protection, never on short card copy | 2026-07-29, a sitewide `pretty` pass changed nothing visible and cost a rework round; 2026-10-19, `pretty` on short card copy left two-word tails in wide cards, caught by the operator in review |

## experiments

| topic | rule | evidence | recheck when |
|---|---|---|---|
| standalone html | grade the file people will receive (the inlined standalone file), not only the linked source. an inlined stylesheet loses its `@import` unless the import leads the style block, and a google fonts url contains `;` inside its quotes, so match `@import url\([^)]*\);` whole and hoist it to the top. the symptom is a fallback sans in the render, and a render diff that jumps from about 1% to 6–20% | 2026-09-17, two debug rounds | next inlined-stylesheet build |
| background servers | start a background dev server with `cd <project> &&` in the same command. a harness that resets the working directory starts it in the wrong folder, and every route returns nothing | 2026-08-26, every route failed until a restart; one round | next background server start |
| stopping servers | stop a server by its port (`lsof -ti :<port> \| xargs kill`). pkill on the command misses a pnpm-spawned child, which keeps serving a stale build (the tell: fonts return 404 at 21 bytes) | 2026-08-26, a stale server kept serving an old build; one round | next server restart |
| long-page captures | the headless `--screenshot` flag blanks above about 12,000 device px and doesn't scroll to anchors; capture with a raw CDP clip against puppeteer's cached chrome-headless-shell, driven by a small dependency-free node websocket script, instead. `next dev` can truncate very large responses, so check page-end content against a production build | 2026-08-30 | next long-page capture |
| interaction probes | scope interactive selectors to `main` or `section`. a bare `button[aria-expanded]` matched the header's menu trigger before the page's own control | 2026-08-26, one capture round | next interaction probe |
| lighthouse floor | a next.js app-router page with a text LCP tops out around 96 on mobile performance on localhost, because Lighthouse's Lantern model charges every script started before LCP, and the react runtime alone is about 130KB gzipped. subsetting fonts and dropping unused weights is the cheap win (130KB to 40KB of fonts took one page from 86 to 96); beyond that, only removing hydration helps. desktop reaches 100 | 2026-08-26 | next performance pass |
| stale dev caches | put structural layout (stacking direction, wrapping) in markup, never in a css rule alone: turbopack dev can serve a stale css chunk after many hot edits, and the stale chunk can survive a dev-server restart. verify the served css (curl the chunk), not the file on disk, and restart the dev server after heavy css-edit sessions. if it still mismatches after a restart, `rm -rf .next` and restart. treat any build error naming a module you just deleted (`ReferenceError: X is not defined` during "collect page data") as a stale cache first: cold-build before reading code | 2026-07-09 a broken live page; 2026-07-10 a restart didn't refresh the chunk; 2026-07-26 four greps chasing a phantom module | next long dev-server session with css edits |
| iframe previews | `X-Frame-Options: DENY` blanks same-origin iframes too, so any page that previews the site in iframes needs `SAMEORIGIN`. after any headers or security change, check that iframe previews render. the browser shows "localhost refused to connect", and curl can't see the failure | 2026-07-10, a blocked morning review | next headers or security change |
| portaled popups | every portaled popup (menu, tooltip, dialog positioner) takes an explicit slot on the project's z scale. portals land at the end of body at z auto and paint behind every positive-z layer, so the popup opens invisibly. markup checks can't catch paint order; look at it | 2026-07-12, a dropdown shipped invisible behind the hero; a review round | next portaled overlay |
| narrow captures | headless chrome on macos clamps its window to about 500px wide, so `--window-size=375,…` renders a 500px layout cropped to 375 and fakes overflow. capture phone widths through a local html page that iframes the url at the target width, or drive chrome over the devtools protocol with `Emulation.setDeviceMetricsOverride` (width, height, `mobile: true`) and `Page.captureScreenshot`; `--headless=old` is gone and no longer escapes the clamp | 2026-10-06, a false 375 overflow on the web-v2 hero; 2026-10-15, a clipped 390 board capture, fixed over cdp in one round | next phone-width capture |
| staged reveals | never stage a reveal (progress cells, typed keys, a drawn tick) as many 1ms css animations on long `animation-delay`s with `fill-mode: both`: in chrome some report `finished` yet hold their from-value, so cells stay dark and pixels go missing. drive staged reveals from js timers, or from a frame loop that sets data attributes the css styles. short real durations (a 200ms pop) are fine | 2026-10-13, a progress track stalled at 13 of 30 cells and a tick lost a pixel; one diagnosis round | next staged reveal |
| tokens reading element vars | a theme token (`--animate-*`, `--shadow-*`, any `:root` custom property) must not `var()` a variable that only elements set (`--chars`, `--row`): custom properties resolve where they are defined, so on the root the reference is missing, the token computes empty, and every utility that reads it silently drops the declaration. write such values out in the utility or class that sets the element variable. check with `getComputedStyle(document.documentElement).getPropertyValue(token)`: empty means broken | 2026-10-13, every typed log line in an animated ui scene had been appearing whole since it was built; found by a frame probe, not by eye | next token that reads a per-element variable |
| webgl under strictmode | a react effect that owns a webgl canvas must not call `WEBGL_lose_context.loseContext()` in its cleanup: strictmode runs the effect twice in dev, the canvas hands the lost context back to the second run, and every gl call no-ops, so the canvas stays blank with no error. delete the program, shaders and buffers instead. pixel-check a webgl canvas with `gl.readPixels` (create it with `preserveDrawingBuffer: true`), because browser-pane screenshots of an unpreserved canvas come back blank or stale | 2026-10-15, a blank shader canvas and one diagnosis round | next webgl canvas in react |
| react flow node identity | in a controlled react flow canvas, never rebuild node objects to carry hover or selection state: new node objects make react flow re-adopt them and drop handle bounds for a frame, so every edge unmounts and remounts (entrance animations replay, lines blink out). build nodes and edges once per layout and pass state through context. when selection is your own, also turn `elevateNodesOnSelect` and `elevateEdgesOnSelect` off, or edges regroup by z-index and remount | 2026-10-18, lines vanished on every hover and selection; two diagnosis rounds and a design-review finding | next react flow canvas |
| react flow camera moves | `setViewport` with a duration runs a d3 transition, and d3-zoom stops it on any mousedown on the pane or a non-draggable node, freezing the camera mid-move. pause drag-panning (`panOnDrag={false}`) for the move's duration, take camera decisions from the move's target rather than `getViewport()`, and detect the viewer's own moves from `onMoveStart`/`onMove` (an event means the viewer, null means your code) instead of comparing views. when a click can move the camera, ignore clicks with `event.detail > 1` (the second click of a double-click lands on whatever slid under the pointer), and resolve each click from its pointerdown target: react flow's pane click fires for a press on a node released on the pane, since the pane contains the nodes. when a panel borrows the camera, give the whole view back on close (pan and zoom), not just the zoom | 2026-10-18, a press mid-reframe stranded the map without labels, double-clicks opened the wrong node, and closes left the map shifted; two grading rounds | next react flow canvas with camera moves |
| hidden preview pane | the app's browser pane runs a hidden page as a background tab: animation frames and css transitions stall, and screenshots come back stale. verify motion and timing with headless chrome captures (`puppeteer-core` against the cached `chrome-headless-shell`), not the pane | 2026-10-18, a stalled panel transition and a stale screenshot read as bugs; one debugging round | next motion check in the pane |
| audit every instance | a text or layout audit run over captures covers only the states the capture opened. when content repeats per item (a detail panel per node, a card per record), drive every instance headlessly and audit each one, scoped to that instance. judge wrapping per rendered text block (the innermost non-inline element), not per element with its own text, or values built from inline spans escape the check | 2026-10-18, captures opened 3 of 21 panels; a fresh grader found two runts in the other 18, costing a grading round | next content-heavy canvas or list |
